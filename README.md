# 2026 NLP Project 1: Num2Text

2026-2 自然语言处理课程小组作业。项目使用 GRU Encoder–Decoder，把数字字符串、英文读法和韩文读法进行互译。

## 支持的方向

| 函数 | 输入 | 输出 |
|---|---|---|
| `num2en(text)` | 数字字符串 | 英文读法 |
| `en2num(text)` | 英文读法 | 数字字符串 |
| `num2ko(text)` | 数字字符串 | 韩文读法 |
| `ko2num(text)` | 韩文读法 | 数字字符串 |
| `en2ko(text)` | 英文读法 | 韩文读法 |
| `ko2en(text)` | 韩文读法 | 英文读法 |

数字输入应传字符串，例如 `num2en("12345")`，不要传整数。

## 文件

- `project01/num2text.ipynb`：数据准备、六个方向的模型训练、测试评估和模型加载示例。
- `project01/num2text_models.pt`：六个已训练模型的权重、词表和模型配置。
- `project01/num2txt.txt`、`project01/num2kor.txt`：数字到英文、韩文读法的数据。

## 运行

需要 Python、PyTorch 和 Jupyter。Notebook 按顺序运行即可；它从 `project01` 目录读取数据并把权重写入同一目录。若在仓库根目录启动 Notebook，代码会自动检查 `project01/` 子目录。

训练完成后，Notebook 最后一节会从 `num2text_models.pt` 载入词表和六个模型，并给出可直接调用的示例。只做推理时，运行最后一节即可，但需要先确保 PyTorch 可用且工作目录为仓库根目录或 `project01`。

## 数据与结果

两份源数据各有 100,000 条。数字作为字符串序列处理；英文按空格分词，韩文按字符切分。两份数据按数字对齐后，英文↔韩文可用的共同数字为 12,738 条，因此这两个方向的训练数据少于数字互译方向。

Notebook 中保存的测试集 exact-match 准确率如下。重训时结果可能因随机初始化而变化；当前代码固定了数据划分种子，但尚未固定 PyTorch 初始化种子。

| 方向 | 测试准确率 |
|---|---:|
| 数字→英文 | 99.68% |
| 英文→数字 | 99.93% |
| 数字→韩文 | 99.77% |
| 韩文→数字 | 98.91% |
| 英文→韩文 | 99.37% |
| 韩文→英文 | 99.22% |

指标为整条输出完全匹配的比例。英韩方向测试集为 1,275 条，其余方向各为 10,000 条。Notebook 会打印少量错误样例，便于检查仍然存在的数字位值错误。
